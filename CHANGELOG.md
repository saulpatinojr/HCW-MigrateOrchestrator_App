## Unreleased

- Release hygiene (ticket AMO-11, issue 52, ADR-0032): `release-cli.yml` is now one ordered workflow with per-job permissions. Seven jobs: `check`, `sea`, `packages`, `inventory`, `attest`, `release`, `post-release`. The workflow level is `contents: read`; only `release` has `contents: write`, only `attest` has `id-token` and `attestations: write`. `release` is the one job that touches the GitHub Release: it creates it as a **draft** with all ten files, checks that the draft holds exactly those files (names, upload state, the sha256 GitHub reports) and only then makes it public; an existing draft or release is never touched and no file is replaced. The third-party `softprops/action-gh-release` is gone; the logic is in `scripts/release-publish.mjs`, tested against a fake `gh`. New: a CycloneDX SBOM for the command-line tool (`amo-cli-<version>.cdx.json`) and one for the two tarballs as a consumer installs them (`hybridcloudworks-migration-packages-<version>.cdx.json`), both from `npm sbom` (`scripts/generate-sbom.mjs`), and `actions/attest` v4.2.2 attests build provenance and the SBOM for each binary and tarball. Attestations are verified with `--signer-workflow`, `--source-ref refs/tags/<tag>` and `--source-digest <commit>` in `attest`, in `release` and in `post-release`. `scripts/check-release-version.mjs` runs first (also in `publish-npm.yml`): the tag must be `v` plus the version in `package.json`, `repository.manifest.json` and `package-lock.json`, and the commit must already be on `main`; `--set-version X.Y.Z` writes all of them. `post-release` downloads the public release and re-runs `npm run packages:verify -- --tarballs released` (the script gained `--tarballs` and `--version`). Both workflows have a concurrency group that never cancels. A dry run that publishes nothing: Run workflow on `main` takes the tag to be `v` plus the package version, runs the same checks and keeps the files as a workflow artifact; `release` and `post-release` run only for a pushed tag. `publish-npm.yml` no longer runs `npm install -g npm@latest` (the Scorecard `PinnedDependenciesID` alert); it uses the npm that ships with Node 26 and stops if it is older than 11.5.1, is split into a read-only `verify` job and a tag-only `publish` job, and a manual run can no longer publish. The released file names are unchanged (the downstream edition's pins keep working); two SBOM files are added. `docs/release/README.md` is the owner runbook, including what a dry run cannot prove. The release workflows use no dependency cache (zizmor's cache-poisoning finding). Review follow-up: `check` also refuses a tag on a commit that is not the tip of `main` unless `.github/workflows` is identical to the tip's (GitHub says a `GITHUB_TOKEN` cannot create a release for a commit that changes workflows, which would only have failed after the permanent attestations were written); the draft is judged from `GET /releases/{id}` with a bounded retry and an asset without a sha256 digest is a problem instead of a skipped check; attestation checks add `--signer-digest` and `--deny-self-hosted-runners`; `publish-images.yml` (inert while `DOCKERHUB_ENABLED` is unset) gets the same first-job check; the runbook takes the version from the tagged commit, not the working copy, and lists what a dry run cannot prove, the independence of the release, npm and image workflows, `npm deprecate` for a bad npm publish, and the first adoption by the downstream edition. Tests: `tests/release/` (38 new). **Not verified:** nothing has run in GitHub Actions; the dry run and then the first real tag are the first live exercise. The `Protect release tags` ruleset (deletion, update and non-fast-forward on `refs/tags/v*`) was already active. The `v0.3.1` tag was moved once before it existed and cannot be repaired. The downstream edition's `docs/whats-new-upstream.md` still needs an entry (two SBOM assets added; the release page now appears only after the draft is checked).
